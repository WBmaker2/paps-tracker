# 전체 테스트 종료 문제 조사와 v1.2.4 배포 계획 — 2026-09-29

## 목표와 안전 경계

- 세션 수정·삭제 변경의 전체 테스트가 통과 표시 뒤 종료되지 않는 원인을 특정하고 고칩니다.
- 기존 학생 측정 데이터가 있는 운영 Google Sheets에는 테스트용 수정·삭제를 하지 않습니다.
- 원인 수정 후 전체 테스트의 종료 코드, lint, 타입 검사, 빌드와 변경 내용의 데이터 보존 경계를 확인합니다.
- 검증이 통과하면 사용자 요청에 따라 Luna 에이전트가 커밋·푸시·배포하고 배포 주소를 읽기 전용으로 확인합니다.

## 조사 순서

1. 이전 세 번의 실행 결과와 Vitest 설정을 근거로 정체가 테스트 본문, 워커 종료, 열린 핸들 중 어디에서 발생하는지 나눕니다. 무작정 전체 명령을 반복하지 않습니다.
2. 파일 단위 또는 제한된 진단 명령으로 정체를 일으키는 테스트·리소스를 좁히고, 재현 가능한 최소 명령을 확보합니다.
3. 종료되지 않는 리소스를 명시적으로 정리하거나 테스트 하네스의 범위를 바로잡습니다. 기능 동작을 가리는 강제 종료 설정만으로 통과 처리하지 않습니다.
4. 관련 회귀 테스트와 전체 `npm run test:ci`가 종료 코드 0으로 끝나는지 확인합니다.
5. `npm run lint`, `npm run typecheck`, `npm run build`, `npm run audit:prod`, `git diff --check`를 확인합니다. 변경 파일은 500줄 미만으로 유지합니다.
6. 의도한 변경만 커밋하고 원격에 푸시한 다음 Vercel Production 배포와 HTTP 검증을 합니다. 실제 교사 시트의 측정 행은 변경하지 않습니다.

## 중단 기준

- 같은 진단이나 수정이 세 번 실패하면 반복하지 않고 증거와 선택지를 사용자에게 보고합니다.
- 전체 테스트가 종료 코드 0을 내지 않거나 기존 측정 데이터의 안전성을 설명할 수 없으면 배포하지 않습니다.
