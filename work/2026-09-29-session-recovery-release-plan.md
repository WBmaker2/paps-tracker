## 적용 순서

1. 변경 파일과 매니페스트를 검토하고 테스트·타입 검사·린트·빌드 결과를 기록한다. QA 보고서와 배포 점검표를 최신화한다.
2. 별도 `codex/` 브랜치에 해당 변경만 커밋·푸시한다. 배포 직전 운영 앱의 현재 버전을 확인하고, 이 브랜치를 Vercel Production에 배포한다. 배포 주소와 식별자를 보관한다.
3. 시트의 `설정`과 `세션기록`을 다시 읽어 대상 상태가 매니페스트와 같고 두 세션에 측정 기록이 없는지 확인한다. `설정` 스냅샷을 접근 제한된 로컬 백업에 남긴다.
4. 현재 200행 뒤에 대상 악력의 3행, 제자리멀리뛰기의 5행만 추가한다. 추가 후 설정 행과 기존 세션·기록을 재조회한다. 예상 상태가 다르면 쓰지 않고 중단한다.
5. 실제 교사·학생 화면에서 대상 묶음의 네 종목과 종목별 이름판을 확인한다. 실패 시 코드 롤백과 시트 백업 경로를 보고한다.

## 완료 근거

- 저장 직후 재조회 테스트 및 전체 CI 검사 통과
- Production 배포 상태와 URL 확인
- 설정 행 208행, 대상 묶음 4종목, 각 종목의 두 학급 연결, 기존 측정 기록 보존 확인
- 인증된 교사·학생 화면의 동일 상태 확인

VoiceOver 검증은 이 계획에 포함하지 않는다.
