# Google Sheets 데이터 무결성과 교사 관리 UX 개선 계획

## 작업 순서

1. **저장 범위 보호**: Google Sheets 읽기·쓰기 범위의 상한과 잘림 지점을 조사한다. 범위를 넘은 행을 조용히 버리지 않도록 막고, 상한에 이른 시트를 읽거나 수정할 때 명확한 오류 또는 안전한 확장 경로를 제공한다. 기존 측정 데이터는 변경하지 않는다. 경계값 테스트와 전체 관련 테스트로 확인한다.
2. **독립 QA 시트 동시 작업 검증**: 실제 사용 시트와 분리된 QA 시트에서 합성 학생·세션만 사용한다. 같은 키의 동시 제출, 재시도, 교사 측 조회 결과를 검증한다. 서버 인스턴스 사이 중복 방지 결함이 확인되면 수정하고 다시 검증한다. QA 시트를 준비할 수 없거나 교사 인증이 필요하면 사용자에게 로그인을 요청하고 기다린다.
3. **교사 세션 삭제·보관·복원 안내 개선**: 확인 전에 실제로 실행될 작업과 영향을 받는 측정 기록 수를 보여 준다. 작업 결과와 오류도 구체적으로 알려 준다. 모바일·키보드 사용성을 확인하고 업데이트 내역에 기록한다.

## 공통 완료 기준

- 각 단계는 앞 단계의 구현·검증이 끝난 뒤 시작한다.
- 실제 사용자의 기존 측정 기록을 삭제하거나 수정하지 않는다.
- 코드 파일은 500줄 미만으로 유지하고, 필요한 기능은 별도 파일로 나눈다.
- 로컬 테스트, 독립 QA 시트 확인, 실제 교사 로그인 확인, 배포 확인을 별도 증거로 기록한다.
- 구현은 Luna 하위 에이전트에 맡기고, 이 문서와 검토는 주 에이전트가 담당한다.

## 2단계 중간 확인 (2026-09-29)

- 독립 모듈 인스턴스 두 개와 공용 모의 시트로 같은 제출 키의 동시 요청을 재현했다. 원본 기록과 학생 요약에 각각 두 행이 생겼다. 제출 응답은 하나로 합치지만, 교사 원본 조회는 중복을 경고하고 대표값 선택을 막는다. 실제 Google Sheets 쓰기 검증은 아직 하지 않았다.
- 이전 QA 시트는 현재 교사 Google 계정에서 접근 거부다. 로컬 서비스 계정 키와 Vercel CLI로 내려받을 수 있는 키는 민감 값 마스킹 문자열이라 테스트 인증에 사용할 수 없다. 실제 사용 시트의 데이터를 시험 대상으로 쓰지 않는다.
- Google Sheets `values.append`만으로는 동시 요청의 동일 키 중복을 원자적으로 막지 못한다. `spreadsheets.batchUpdate`의 `CreateDeveloperMetadataRequest`에서 지정 ID 충돌을 검사하고 같은 일괄 요청에 `AppendCellsRequest`를 넣는 방식은 원본 행 추가에 한정된 원자적 중복 방지 후보이다. 메타데이터 문자 한도, ID 해시 충돌, 기존 행 이행, 요약 갱신 경합을 설계하고 독립 QA 시트에서 시험한 뒤 적용 여부를 결정한다.

## 중간 배포 결정

- 사용자의 2026-09-29 커밋·푸시·배포 요청에 따라 1단계 저장 범위 보호와 2단계 동시성 재현 테스트만 먼저 배포한다.
- 실제 QA 시트 검증과 원자적 중복 방지, 3단계 교사 세션 안내는 이번 배포에 포함하지 않는다. 이번 배포는 동시 제출 중복을 해결했다고 표시하지 않는다.
- 앱 업데이트 내역과 버전을 갱신하고, 전체 테스트·정적 검사·빌드·운영 의존성 감사 후 배포한다. 공개 상태·인증된 교사 상태는 읽기 전용으로 확인한다.
