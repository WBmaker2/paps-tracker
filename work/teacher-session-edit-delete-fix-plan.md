# 교사 세션 종목 수정·삭제 복구 계획 — 2026-09-29

## 사용자 요구와 데이터 경계

- 교사가 기존 세션의 측정 종목을 수정하고, 더 이상 사용할 세션을 목록에서 제거할 수 있어야 합니다.
- 기존 학생 측정 시도·동기화 상태·감사 기록은 수정하거나 삭제하지 않습니다. 운영 Google Sheets에는 재현용 쓰기를 하지 않습니다.
- 실제 교사 계정의 화면은 사용자가 로그인·시트 연결 준비를 알린 뒤 읽기 전용으로 확인합니다.

## 확인된 원인 후보와 재현

1. 세션 목록 컴포넌트에 삭제 버튼이 없어서, 이미 존재하는 `DELETE /api/sessions/[sessionId]` 기능에 교사가 접근할 수 없습니다.
2. 기존 세션 묶음의 종목을 줄이는 `POST /api/sessions`는 새 세션을 저장한 다음 빠진 세션을 삭제합니다. Google Sheets 저장 헬퍼는 각 요청의 `state.sessions`를 갱신하지 않아 뒤의 삭제가 앞의 저장 결과를 오래된 세션 목록으로 덮어쓸 수 있습니다. 가짜 Sheets 왕복 재조회 테스트로 먼저 재현합니다.
3. 기록이 있는 묶음은 종목 추가를 포함한 모든 구조 변경을 일괄 차단하고, 화면의 체크박스도 전부 비활성화합니다. 기록이 달린 기존 종목의 ID·종목·학급을 바꾸거나 삭제할 수 없다는 제한은 유지하되, 새 종목 추가와 기록 없는 종목 제거가 가능한지 안전성을 검증합니다.
4. 현재 `DELETE` API에는 측정 기록 사전 확인이 없고, 데모 저장소는 세션 삭제 시 관련 측정·감사 행도 지웁니다. API에서 기록 보존 경계를 강제해야 합니다.

## 구현 순서

1. 위 원인을 각각 실패하는 테스트로 고정합니다. 단일·묶음 세션, 기록 유무, 세션 수정 후 재조회와 삭제 후 재조회, 권한 범위를 포함합니다.
2. 세션 묶음 수정 시 최종 세션 목록을 일관되게 저장하고 Google Sheets 설정 행을 한 번만 갱신합니다. 실제 측정 탭에는 쓰지 않습니다.
3. 삭제 동작을 교사 목록에 명확히 추가하고, 세션 묶음은 전체 자식 세션을 대상으로 한 번의 확인·서버 검증·설정 저장으로 처리합니다. 기록이 없는 세션은 설정 행에서 삭제하고, 기록이 있는 세션은 원본 기록과 세션 메타데이터를 남긴 채 활성 목록에서 보관합니다. 보관된 세션은 복원할 수 있습니다. 원본 측정·감사 행을 지우는 하드 삭제는 허용하지 않습니다.
4. 수정 폼은 기록 있는 종목의 불변 조건을 설명하고, 안전한 범위의 종목 추가·기록 없는 종목 제거를 허용합니다. 저장 실패 원인을 한국어로 표시합니다.
5. 업데이트 내역과 릴리스 문서에 변경을 기록하고, 모든 코드 파일을 500줄 미만으로 유지합니다.

## 검증 게이트

- 관련 테스트에서 문제를 먼저 재현하고 수정 후 통과시킵니다.
- 전체 `npm run test:ci`, `npm run lint`, `npm run typecheck`, `npm run build`, `git diff --check`를 실행합니다.
- 가능하면 연결된 교사 화면에서 읽기 전용 UI 확인을 수행합니다. 실제 삭제·수정 클릭은 독립 QA 시트에서만 실행하며, 접근 권한·기존 행 범위를 확인하기 전에는 쓰지 않습니다.
- 이번 요청은 로컬 수정·검증이며 커밋·푸시·배포는 별도 요청이 있을 때 진행합니다.
