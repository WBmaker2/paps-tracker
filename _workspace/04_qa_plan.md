# QA 계획: 체지방 제외 4요인 회차 결과

## 목적

- 학생별 네 요인의 대표 측정값이 모두 준비된 경우에만 서버가 점수와 등급을 계산·확정하는지 검증한다.
- 체지방·BMI가 생성 요청, 측정 진행, 계산, 등급, 결과 저장과 화면에 데이터 필드로 들어가지 않는지 검증한다.
- 기존 종목별 세션, 대표값, Google Sheets 제출·요약 흐름이 유지되는지 확인한다.

## 범위

### 포함

- 종목별 공식 세부 점수 0~20 경계와 4요인 합계·환산점수·등급
- 회차 생성, 대표값 기반 preview, 단건·일괄 확정, revision·stale·멱등성
- Google Sheets 설정 메타데이터와 `4요인회차결과` 탭 직렬화·복원
- 교사 회차 생성·결과 확정 UI와 학생 0/4~4/4 진행·확정 결과 UI
- 기존 전체 회귀, 린트, 타입 검사, 프로덕션 빌드
- 390×812 학생 화면 및 일반 공개 경로 브라우저 스모크

### 제외

- 체지방, BMI, 공식 PAPS 5요인 종합점수·종합등급
- 실제 운영 Google OAuth 계정과 운영 시트에 대한 쓰기
- 커밋, 푸시, 배포

## 검증 순서

1. 공식 별표 5 예시와 모든 지원 학년·성별·종목 규칙 fixture를 단위 테스트한다.
2. 한 요인 누락, 4요인 경계 15/16·31/32·47/48·63/64, 환산 `×1.25`를 검증한다.
3. 회차 저장소의 ready → finalized → replay → stale → 새 revision 흐름을 검증한다.
4. 설정 탭·회차 결과 탭의 직렬화와 재로딩, 기존 v0.1 시트 보존 경로를 검증한다.
5. UI 요청 본문과 결과 adapter에 체지방·BMI 데이터 필드가 없고, 사용자 전환 시 진행 정보가 섞이지 않는지 검증한다.
6. 전체 테스트·린트·타입 검사·빌드를 Node 22에서 실행한다.
7. 로그인 없이 확인 가능한 공개/학생 경로를 데스크톱과 390×812에서 브라우저 스모크한다.

## 차단 기준

- 네 대표 기록이 없는데 점수·등급이 생성됨
- 체지방/BMI 데이터 필드가 요청·응답·시트 결과에 포함됨
- 클라이언트가 보낸 점수나 등급을 서버가 신뢰함
- 확정 revision이 덮어써지거나 대표 기록 변경 후 stale가 되지 않음
- 회차 연결 세션/반 삭제로 저장된 회차가 고아 상태가 됨
- Google Sheets 결과 스냅샷을 다시 읽을 수 없음
- 기존 테스트, 린트, 타입 검사 또는 빌드 실패

## 브라우저 제약

교사 회차 생성·확정의 실제 브라우저 흐름은 허용된 Google OAuth 계정과 편집 가능한 시트가 필요합니다. 현재 로컬 QA에서는 해당 외부 계정에 쓰지 않고 컴포넌트/API 테스트로 검증하며, 공개 랜딩과 데모 학생 입력 경로만 실제 브라우저로 확인합니다.
